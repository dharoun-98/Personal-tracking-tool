## What this release is

A genuinely playable game. Someone can open the app, answer eleven questions,
and walk away with a board that fits their life — then log against it every day
and watch seven orbs brighten or dim honestly.

It is entirely local-first. No account, no server, no network calls. That was a
deliberate sequencing choice: it meant the *game* had to be good before any
infrastructure existed to hide behind.

## Architecture decisions worth remembering

### Local-first, with a seam for Supabase

All state lives in one Zustand store persisted to `localStorage`
(`src/lib/store.ts`). The action surface is narrow and fully serialisable, so
Stage 3 can back it with Supabase without a single component changing.

Rehydration uses `skipHydration: true` plus an explicit `rehydrate()` from
`StoreHydrator`. Reading `localStorage` is synchronous, so the default
behaviour would rehydrate *during store creation* — before React mounts —
making the first client render disagree with the server HTML.

### Local day keys, never UTC timestamps

Every date is a local `yyyy-MM-dd` string (`src/lib/date.ts`). A habit done at
11pm belongs to that day for the player. Storing UTC and formatting later is
how streak trackers lose a day for everyone east of London.

### The coach is rules, not a model

`src/lib/coach.ts` is ~15 prioritised rules over hand-written copy banks, one
bank per personality. Line selection is a deterministic hash of the rule id and
the day, so the companion doesn't reshuffle its own dialogue on every re-render
but still varies day to day.

This is free, instant, offline-capable, and can never say anything unhinged.
The hard constraint encoded throughout: **it must never nag.** Every rule
declares a cooldown, most fire once a day at most, and nothing uses shame as a
motivator.

### Messages are pushed, not derived

The companion's bubble lives in its own store (`src/lib/companion.ts`) and is
written by whatever caused it — a completed quest, a tap. Deriving it
reactively from game state loops: writing the cooldown for the message being
shown immediately changes which message the selector returns.

### Streaks don't punish an unfinished today

`questStreak` walks back over days the quest was actually due, and the *current*
period never breaks a streak. Being told at 9am that you've failed an evening
habit is exactly the friction this app exists to remove.

### Vitality vs. level

Two separate signals, deliberately. **Level** is cumulative and only ever goes
up — it's the record of what you've done. **Vitality** is a recency-weighted
adherence score over 14 days (half-life ≈ 5 days) — it's how alive that part of
your life is *right now*, and it decays. Orb brightness shows vitality; the ring
shows level progress.

### Starting boards are deliberately small

`generateStarterQuests` caps at 8 quests, only gives quests to the top three
priorities, and budgets against the player's stated daily minutes. Other domains
start dormant, which the orb design reads as an invitation. Deleting a wall of
auto-generated habits on day two is how people quit.

## Notable implementation details

- **Icons** are generated by a hand-written PNG encoder
  (`docs/tooling/generate-icons.mjs`) rather than a build dependency — four
  images, once, without adding `sharp` and its native build step.
- **The star field** uses a seeded PRNG so server and client render identical
  markup. `Math.random()` here would throw a hydration mismatch on every load.
- **Time is an external store** (`src/lib/use-now.ts`, via
  `useSyncExternalStore`) so render stays pure and every subscriber ticks
  together instead of running its own drifting interval.
- **Button styles** live in a non-`"use client"` module so server components can
  render links that look like buttons.
